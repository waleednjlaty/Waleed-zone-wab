# Certified CMP setup — operator workflow

Keep `ADSENSE_PRIVACY_READY=false` and `ADSENSE_ENABLED=false` until the complete integration is tested. This repository contains a consent boundary, not a certified banner/CMP. Do not substitute a homemade consent button or a test __tcfapi stub for a real certified provider.

1. Select Google Privacy & Messaging from the real AdSense account, or another **currently Google-certified web CMP**. Check Google's current provider list and the provider's integration instructions; certification is not a legal-compliance guarantee.
2. Configure the actual site and its privacy notice. Review GDPR/EEA, UK and Switzerland messaging and all applicable traffic settings with the operator. This application conservatively requires affirmative Google vendor/purpose consent globally, with no non-personalized or limited-ad fallback on refusal.
3. Obtain/confirm the provider's TCF CMP ID, not a vendor ID, and set `ADSENSE_CMP_ID` to that ID. Integrate the provider's documented bootstrap and visible preference-reopening/withdrawal control in a separately authorized staging change. Google Privacy & Messaging may use account-specific tag instructions: do not add adsbygoogle.js solely for verification or break the no-AdSense-before-consent boundary. If the chosen bootstrap cannot satisfy that boundary, evaluate a certified provider with an independent bootstrap before serving.
4. Confirm live `__tcfapi('addEventListener', 2, callback)` responses: successful callback, expected CMP ID, loaded state, settled event, TC string, Google vendor 755 consent and purposes 1/3/4 with no publisher restrictions. The API version argument remains 2; use the provider's currently required TCF string format. Google's documentation requires TCF v2.3 for newly generated strings since March 1, 2026.
5. Add exact CMP CSP origins **only if required and verified**. Preserve nonce-based scripts and Phase 8 restrictions. Do not permit blanket https: script/connect access, unsafe-inline scripts, or speculative wildcard hosts. The consent bootstrap and preference controls require their own CSP review.
6. With all serving gates/slot enabled **only in network-isolated fixtures or separately authorized staging**, test fresh visitors with no answer, denial, grant, wrong/failed/missing CMP, preference reopening, withdrawal and reload. Download access remains available independently of consent.
7. Inspect network requests: before affirmative consent there must be no Google AdSense SDK/ad request. After grant there is one manual slot/SDK, never duplicate injection. Withdrawal removes inventory and prevents new pushes. Removing markup cannot undo a loaded third-party SDK: verify the real provider's withdrawal, cookie handling and reload behavior.
8. Repeat at 360/768/1440 and on every excluded route, including /download, legal and error pages. Do not send test publisher IDs to Google. Update the published privacy/contact notice to match the real configuration.
9. Only after all of this passes set `ADSENSE_PRIVACY_READY=true` as an operator attestation. Site approval/content review/final serving remain separate gates. Follow [the activation checklist](ADSENSE_ACTIVATION_CHECKLIST.md).

No real account/provider configuration was performed in this PR. Check the current [Google-certified CMP list and requirements](https://support.google.com/adsense/answer/13554116) and [TCF integration documentation](https://support.google.com/adsense/answer/9804260) before operator setup (references reviewed 2026-10-04).
